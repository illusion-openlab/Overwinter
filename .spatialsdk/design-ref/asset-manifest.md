# 《越冬》素材清单 v1

供图像生成 / 美术产出使用。参考风格以 `ref-artboard.png`、`ref-spritesheet.png` 为准。

- **设计基准**：1040 × 580 dp 平面窗口（`WindowContainer`）
- **出图密度**：全部按 **2×** 出（1dp = 2px）
- **交付格式**：PNG（带 alpha）。落库前我统一转 WebP 压缩
- **总计**：27 项，预估包体 2.5 ~ 3.5 MB

## 0. 六条硬约束

这几条不满足，素材做出来也用不了。按重要性排序。

### ① 背景纸底不要画进素材

素材内部的水彩颗粒、渗色、笔触**要保留**——那是质感本身。但**米色纸底必须是透明的**。

现在这两张图的问题就在这：`ref-spritesheet.png` 的 alpha 通道全是 255，米色 `(246,242,236)` 是实色画进去的。水彩边缘是柔的、半透明的羽化，从实色底上抠必然留一圈米边。

如果生成器不支持透明输出，退而求其次：**用纯品红 `#FF00FF` 平涂底**（不要米色、不要白色、不要任何接近素材颜色的色），这样能干净抠出来，羽化边还能保留半透明。

纸纹作为**单独一张可平铺贴图**（第 14 项），运行时正片叠底盖全屏——这样所有元素共享同一层纸纹，不会拼出接缝。

### ② 节疤横向不许超出 76dp

碰撞体是 76dp 宽的矩形。树干上的断枝节疤**横向最远只能到 ±38dp（±76px）**，也就是说素材的内容宽度上限是 152px。

`ref-spritesheet.png` 里的树干侧枝伸出主干约 40px（主干才 60px 宽），换算过来严重超界。超界的后果是：小鸟从旁边掠过时，**看着穿过了树枝却没死**。Flappy 类游戏的口碑全押在这个判断上。

要森林感就交给背景的雪松林和远山，障碍本身保持利落的竖直剪影。

### ③ 树干上下端必须硬切

树皮一直画到画布上下边缘为止——**不要留白、不要收口、不要画成一段完整的木头**。

因为障碍要从画面边缘一路延伸到缝隙边，长度不固定，我会从**远离缝隙的那一端**按需裁掉。那一端本来就在屏幕外，硬切边才裁得干净。

### ④ 判定边要能一眼看出来

- 上障碍的判定线 = **冰柱最长那根的尖端**。所以冰柱长度要尽量一致，相差 ≤ 6px
- 下障碍的判定线 = **积雪冠的最高点**。所以最高点要在正中，不要偏到一侧

我会用脚本从 alpha 通道自动算出这两条线，不需要你对齐到具体像素——只需要形状别做得太参差。

### ⑤ 两种收集物的剪影必须一眼分得开

浆果是**红色、饱和、成簇的实心圆**；花朵是**白色、低饱和、松散的花瓣**。它们在游戏里买的东西完全不同——浆果回体温（命），花朵加分（奢侈品）——所以玩家必须能在余光里瞬间分辨。

不要把花画成一团圆滚滚的白色小球，那样和雪覆盖的浆果太像。

顺带一条摆放规则（我这边实现时遵守，你出图时按 72×72px 的内容框留好余量）：**收集物中心距碰撞判定线 ≥ 30dp（60px）**，整体不得越过判定线。上一版效果图里花枝有约 14dp 压在死亡矩形里，看着能吃、去够就撞死——这类"骗人"的元素比不好看严重得多。

### ⑥ 小鸟只出「机身 + 单翅」，不要出帧序列

**这条从「两条路线都出」改成了硬性要求**，因为帧序列这条路已经逐帧量过、证伪了：

| 帧 | 机身宽 px | 翼尖方位角 |
|---|---|---|
| 0 | 135 | −112.3° |
| 1 | 129 | −105.1° |
| 2 | 121 | −105.7° |
| 3 | 134 | −93.1° |
| 4 | 124 | −110.6° |
| 5 | 108 | −110.9° |

（方位角以机身中心为原点，−90° = 正上方，+90° = 正下方）

**翼尖总行程只有 19°**，全落在「上举偏后」一个区域，**没有一帧翼尖低于水平**；机身宽度极差 25%。连播出来是「原地抖 19 度 + 身体一大一小」。

改成机身 + 单翅之后，翅膀在运行时绕肩点旋转，拍打的行程、快慢、力度都能算出来：

| 参数 | 值 |
|---|---|
| 旋转中心 | 肩点（我从素材里标定，你不用对齐） |
| 行程 | `+16° → −76°`，共 92° |
| 下扑 | 占周期 30%，**加速**（u²） |
| 回收 | 占周期 70%，**减速**（1−(1−v)^2.4） |
| 拍打速率 | 随上升速度提高；下落时收敛到滑翔角 +1°，只留余振 |

对素材的两条要求：

1. **`bird_body.png` 的背部必须画全。** 翅膀会移开，原本被翅膀盖住的那块背要有内容，不能是缺口。（我这轮在预览里是用邻域填色补出来的，能用但不是画的。）
2. **`bird_wing.png` 的翅根要画到肩点位置**，不要只画外侧那截羽毛——不然大角度下扑时会和身体脱开。

#### 如果你还是想要帧序列

那必须重出一排**真的含下扑帧**的。可直接粘贴：

> 一排 6 帧小鸟飞行动画序列，横向排列，间距均匀。水彩 / 水粉厚涂，童书插画质感，颜料颗粒感，柔和羽化边缘。金黄色小鸟侧视朝右，圆胖体型，灰褐色翅膀，橙红色喙和尾羽。
>
> **6 帧之间机身大小、朝向、头和眼的位置必须完全一致，只有翅膀角度在变**，像同一只鸟被逐帧拍下来。翅膀角度依次为：
> ① 高举过背（翼尖在头顶上方）② 斜上 45° ③ 水平展开 ④ **斜下 45°（翼尖低于腹部）** ⑤ **完全下扑（翼尖指向正下方，压在身体下面）** ⑥ 回收上抬中
>
> 第 ④ ⑤ 帧是关键，必须能看到翅膀在身体下方。透明背景（若不支持则用纯品红 #FF00FF 平涂底），不要纸张纹理背景，不要投影，不要边框，不要文字标注。

收到后我会重新量一遍翼尖行程，达不到 80° 就退回机身 + 单翅。

## 2. 体温变色怎么保住

改成位图后，「体温低 → 整张画面告诉你快不行了」这个核心表达仍然成立，靠四条：

| 手段 | 作用层 |
|---|---|
| 5 张远山氛围图交叉淡入 | 天空 + 远山（占画面上半，氛围主要靠它） |
| 运行时染色（正片叠底往冷蓝走 + 降饱和） | 雪松、雪地、树干、花朵（全强度）；小鸟、浆果（半强度，永远最暖） |
| 粒子密度与下落速度 | 飘雪 |
| 整体 alpha | 四角霜华 |

温度 → 氛围映射（相邻两档交叉淡入）：

```
100°  mountains_day        晴日
 75°  mountains_overcast   阴雪
 50°  mountains_golden     金色黄昏
 25°  mountains_dusk       紫暮
  0°  mountains_night      蓝夜
```

## 3. 生成建议

**成组出图，不要逐个出。** 同一张图内部风格一致性远好于分次生成——你现在这两张图就是这么做的，效果很好。建议按上面的 A/B/C/D/E 五组分五次。

**风格关键词**（沿用现有两张图的调性）：

> 水彩 / 水粉厚涂，童书插画质感，颜料颗粒感明显，柔和羽化边缘，蓝灰与赭黄为主的北欧冬季配色，柔和自然光

**每组提示词末尾统一附加**：

> 透明背景（若不支持则用纯品红 #FF00FF 平涂底），不要画纸张纹理背景，不要投影，不要边框，不要文字标注，元素之间留足间距不重叠

**色彩参考**（取自 `ref-spritesheet.png` 的色卡）：

| 用途 | 色值 |
|---|---|
| 天空 / 远山 | `#8FA8BE` `#A8C4DA` |

## 4. 收到素材后怎么验

校验脚本已经写好了，你出完素材可以自己先跑一遍：

```bash
python3 .spatialsdk/tools/validate-assets.py <素材目录>
```

它会检查：

- 画布尺寸对不对、**alpha 是不是真的有透明区**（这条会直接拦住「纸底画成实色」的素材）
- 每张 `trunk_*` 的最大内容宽度 ≤ 152px，上下端是否硬切，枝头端 200px 内有没有节疤
- 从 alpha 算出每张 `cap_top_*` / `crown_bot_*` 的**判定线**，顺带报冰柱根数、带高、参差；冠的最高点偏不偏心
- 结果写进 `assets-collision.json`，实现时直接读

输出分三档：**阻塞**（必须重出）、**警告**（能用但会影响手感）、**实测**（只是把数值报给你看）。

之后我做：

1. 全部转 WebP，量包体
2. 更新设计契约的元素表（素材文件名 + 判定线数值）
3. 契约确认后才 `pico-cli project create`
